# Deploying Verbo on Render

`render.yaml` defines the web service and Postgres, both on Render's free plans, so no card is needed.

## Steps
1. Choose **New → Blueprint**, connect the `Vrinda072/verbo` GitHub repository, and select the `main` branch.
2. Render asks for each value below. Copy them from your local `.env`, after rotating any key that was pasted in chat.
   - `GEMINI_API_KEY`, `GROQ_API_KEY`, `AG_STUDIO_LICENSE_KEY`, `ELEVENLABS_API_KEY`
   - `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`
   - `SANDBOX_SENDER_EMAIL`, `SANDBOX_INTENDED_RECIPIENT_EMAIL`, `SANDBOX_WRONG_RECIPIENT_EMAIL`
3. Apply the Blueprint, wait for the first deploy, then open the `.onrender.com` link.

`TOKEN_SIGNING_SECRET` is generated by Render. `DATABASE_URL` and the public URL are set automatically.

## Modes
The Blueprint starts with `MOCK=1`, so judges can try the whole flow without a PayPal login, and no PayPal call is made.

To use the real PayPal sandbox, first run the hold and recovery flows through the app, then set `MOCK=0` on the web service
and the job. Also add a job that runs `npm run release-holds` every few minutes with the same PayPal variables. In mock
mode the app releases holds itself, and that job wouldn't work, because mock payments live in the web process's memory.

## Free plan limits
- The web service sleeps after 15 idle minutes; the first visit after that takes longer while it starts.
- The free Postgres expires 30 days after it is created. Upgrade it, or recreate it, before then if the demo must stay up.
- Render has no free cron plan, so the hourly recovery job (24-hour reminders, 72-hour escalations) is not deployed.
  To add it on a paid plan, create a Cron Job with schedule `0 * * * *`, command `npm run recovery-tick`, and the same
  `MOCK`, `PAYPAL_ENV`, `DATABASE_URL` and `TOKEN_SIGNING_SECRET` as the web service.
