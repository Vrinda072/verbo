# APIMatic in Verbo

## PayPal Server SDK
`lib/paypal/sdk.ts` creates every PayPal order through `@paypal/paypal-server-sdk`, which is generated by APIMatic and runs on
`@apimatic/core`. It replaced hand-written request code for order creation, including OAuth and request models.

Checked against the PayPal sandbox on Nov 10, 2026:
- `createOrder` returned `PAYER_ACTION_REQUIRED` and a `sandbox.paypal.com` approval link.
- Repeating the call with the same `PayPal-Request-Id` returned the same order, so a retry can't create a second one.

The other PayPal calls stay in `lib/paypal/real.ts`, each checked against PayPal's OpenAPI specs. Payouts and webhook
verification aren't among the endpoints this SDK covers.

## PayPal Context Plugin
Installed for Claude Code on Nov 10, 2026 with `npx context-plugins install paypal --targets claude`, then used to review order
creation. Its implementation skills target a separate generated SDK (package `paypal`), so Verbo did not switch SDKs. The review used
the plugin's operation map and its integration checklist.

| Checked | Result |
| --- | --- |
| `POST /v2/checkout/orders`, `PayPal-Request-Id` header, `body` required | Matches `lib/paypal/sdk.ts` |
| `Prefer` defaults to `return=minimal` | Verbo sends `return=representation`, which it needs for the approval link |
| A timeout is an unknown outcome, not a failure | Covered: the request id comes from the transfer id, so a retry joins the same order |
| Reject a duplicate write with a store constraint | **Fixed.** A simultaneous second request failed on the primary key and reported an error. It now returns the winning record (`tests/doubleTap.test.ts`) |
| Request fields use the right declared types | **Fixed.** `shippingPreference` used another enum with a cast. It now uses `PaypalWalletContextShippingPreference` |
